# 设置

**登录管理页面后，点击头像 → 系统设置，即可进入设置页面。**

---

## 系统配置

### 站点名称

在此项中可以自定义站点标题，便于识别和管理。

### 语言设置

设置软件的语言，主要影响通知与错误信息。

同时可以联动网页界面，实时更改语言。

### 自定义代码

此项用于在网页界面中添加自定义样式或脚本代码，例如修改 Logo、背景图、主题、外链或统计代码。

此项分为两类：

- **用户前端自定义代码**：对应配置文件中的 `custom_code`，会注入公开访问的用户前端。
- **管理前端自定义代码**：对应配置文件中的 `custom_code_dashboard`，只会注入登录后的管理前端。

下面这些全局变量仅由用户前端读取，放入管理前端自定义代码不会生效。请在用户前端自定义代码中通过 `<script>...</script>` 设置；布尔值使用 `true` / `false`，不要写成字符串。

- `window.CustomBackgroundImage`：桌面端背景图 URL。
- `window.CustomMobileBackgroundImage`：移动端背景图 URL，未设置时会沿用桌面端背景图。
- `window.CustomLogo`：Logo 图片 URL。
- `window.CustomDesc`：首页描述文本。
- `window.CustomLinks`：自定义外链，值必须是可被 `JSON.parse` 解析的 JSON 字符串，格式为 `[{"name":"GitHub","link":"https://github.com/nezhahq/nezha"}]`。
- `window.ForceTheme`：强制默认颜色主题，值为 `"light"` 或 `"dark"`。
- `window.ShowNetTransfer`：是否在服务器卡片显示上下行流量。
- `window.DisableAnimatedMan`：是否关闭默认动画人物插图。
- `window.CustomIllustration`：自定义插图 URL。设置后会替换默认插图，通常不需要再启用 `window.DisableAnimatedMan`。
- `window.FixedTopServerName`：是否固定顶部服务器名称。
- `window.ForceUseSvgFlag`：是否强制使用 SVG 旗帜。
- `window.ForceShowServices`：是否默认展开首页服务监控面板。
- `window.ForceCardInline`：是否在非移动端强制使用服务器横向列表布局；移动端仍会使用卡片布局。
- `window.ForceShowMap`：是否默认展开首页地图。
- `window.ForcePeakCutEnabled`：是否默认开启网络图表的峰值裁剪，用于降低突发尖峰对图表可读性的影响。

用户前端示例：

```html
<script>
  window.CustomLogo = "https://example.com/logo.png";
  window.CustomDesc = "My Monitor";
  window.CustomLinks = JSON.stringify([
    { name: "GitHub", link: "https://github.com/nezhahq/nezha" }
  ]);
  window.ForceTheme = "dark";
  window.ForceShowServices = true;
</script>
```

- 管理前端
    1. `window.DisableAnimatedMan`：布尔值，开/关动画人物插图

### 主题

主题设置用于选择用户前端展示模板，对应配置文件中的 [`user_template`](/configuration/dashboard.html#user-template)。管理前端模板对应 [`admin_template`](/configuration/dashboard.html#admin-template)，通常保持默认即可。

内置主题由官方维护；社区主题来自社区贡献，可能不会随 Dashboard 版本同步更新。使用社区主题前请确认来源可信、兼容当前版本，并了解其自定义代码、外链资源或样式变更带来的风险。

### Agent 对接地址

- 此项为使用一键脚本安装 Agent 的必要设置。  
- 设置内容为你希望使用的 Agent 连接地址，例如：`data.example.com:8008`。  
- 如果 Agent 通过 HTTPS、Dashboard 内置 HTTPS 或已在反向代理/CDN 上完成 TLS 终结连接，请启用 **Agent 使用 TLS 连接**，生成的安装命令会带上 TLS 参数。
- 如果 Agent 直连明文 `host:port`，请不要启用 TLS，否则安装命令会让 Agent 按 TLS 方式连接，可能导致无法上线。
- 详情请参考 [Agent 安装准备工作](/guide/agent.html#%E5%87%86%E5%A4%87%E5%B7%A5%E4%BD%9C)。

### 面板 OAuth2 回调域名

用于指定 Dashboard 对外访问并接收 OAuth2 回调的地址，格式为 `域名/IP[:端口]`，不要填写协议或路径；使用 HTTP/HTTPS 默认端口时可省略端口。它与 **Agent 对接地址** 相互独立：前者服务于浏览器登录回调，后者服务于 Agent 连接和安装命令。

启用 OAuth2 时建议显式填写，尤其是 Dashboard 位于反向代理后方，或公网访问域名与 Agent 对接地址不同时。留空时 Dashboard 会信任请求中的 Host；反向代理还应正确传递原始 Host，并通过 `X-Forwarded-Proto: https` 告知外部协议。配置字段为 [`dashboard_host`](/configuration/dashboard.html#dashboard-host)。

### Dashboard 保留域名

用于声明 Dashboard 对外访问使用的其它域名，防止普通成员在 NAT 中创建与 Dashboard 入口冲突的域名。这些域名也会被视为可信的 OAuth2 回调 Host。多个域名使用英文逗号分隔，并在 OAuth2 提供方登记相应回调地址。配置字段为 [`reserved_hosts`](/configuration/dashboard.html#reserved-hosts)。

### DDNS 的自定义公共 DNS 名称服务器

用于 DDNS 功能查询域名 SOA 记录，如不填则采用内置列表。

### 前端真实 IP 请求头

用于识别访问管理前端和用户前端的真实客户端 IP。在线用户、审计记录、登录防爆破和 Web 应用防火墙都依赖它。

直连公网时选择 **使用直连 IP**；通过 Cloudflare 时通常填写 `CF-Connecting-IP`；通过 Nginx、Caddy、Apache 等反向代理时，需要代理传递 `X-Real-IP`、`nz-realip` 或其它同名 Header。完整配置场景、反向代理示例、验证和恢复方法见 [前端真实 IP 请求头](/guide/q12.html)。

### Agent 真实 IP 请求头

- `CF-Connecting-IP` 是一个用于获取 Agent 真实 IP 的请求头字段。  
- 当 Agent 通过 Cloudflare CDN 代理连接 Dashboard 时，启用此功能可以让源服务器正确识别 Agent 的真实 IP。  

### MCP 开关

用于启用或关闭 Dashboard 的 MCP 入口。启用后可使用 PAT 调用 `POST /mcp`；关闭时会拒绝新的 MCP 请求并中断相关传输。配置字段为 [`enable_mcp`](/configuration/dashboard.html#enable-mcp)，认证和权限说明见 [API 接口 - MCP 接入](/guide/api.html#mcp-%E6%8E%A5%E5%85%A5)。

### 在线统计范围（天）

此项对应 [`online_stats_days`](/configuration/dashboard.html#online-stats-days)。默认 7 天，可填写 7–3650 之间的整数，同时控制服务器在线历史的保留与最大查询范围。它不改变 TSDB 指标保留期，也不会把默认用户前端的 1/7/30 天选项扩展为任意天数。

缩短范围后，超出窗口的已结束会话会被定期删除；之后再延长不能恢复已删除的历史。展示方式见[在线历史](/guide/servers.html#在线历史)。

### IP 变更提醒

此功能允许在服务器 IP 地址变更时发送通知，设置步骤如下：

#### 配置选项

1. **覆盖范围**  
   选择一条规则以确定需要监控哪些服务器。

2. **特定服务器**  
   配合覆盖范围设置。覆盖范围为 **覆盖全部** 时，这里表示 **排除特定服务器**；覆盖范围为 **忽略全部** 时，这里表示 **仅特定服务器**。

3. **提醒发送至通知分组**  
   选择通知方式（通知方式需提前在“通知”页中设置）。

4. **启用功能**  
   设置完成后，勾选 **启用** 才会使通知生效。

5. **通知中显示完整 IP 地址**  
   默认情况下，IP 变更通知会隐藏完整 IP 地址。  
   如需显示完整 IP 地址，可勾选此选项。

## API Tokens

此标签页用于创建和吊销 Personal Access Token（PAT）。PAT 适合自动化脚本、CI、LLM 工具和 MCP 客户端使用。

普通成员进入设置页时只会看到 **API Tokens** 标签页；其它系统配置、用户管理、在线用户和 Web 应用防火墙等标签页仅管理员可见。

创建 Token 时可以选择 scope、可访问的服务器 ID 白名单和过期时间。Token 明文只会在创建成功后显示一次；后续列表只会展示权限、服务器白名单、过期时间、最后使用时间和最后使用 IP 等元信息。认证格式和 scope 说明见 [API 接口 - Personal Access Token](/guide/api.html#personal-access-token-pat)。

## 数据库

此标签页显示 SQLite 数据库的占用，并可以手动清理较早的服务监控历史，以减小数据库和[备份](/guide/backup.html)的体积、缩短恢复耗时。仅管理员可见。

未启用 TSDB 时，服务监控历史保存在 SQLite 的 `service_histories` 表中，不会自动清理，数据库会随运行时间持续变大。

### 占用与估算

页面上方显示当前状态：

- **数据库占用**：数据库文件的大小，包含尚未合并的 WAL 文件。
- **现在压缩可回收**：数据库里已经空出、但文件尚未缩小的空间，压缩后才会还给磁盘。
- **服务历史记录数** 和 **最早记录**。
- **磁盘剩余空间**：数据库所在磁盘的剩余空间，无法获取时显示为未知。

选择保留天数后，页面会估算本次清理：将删除的记录数、预计释放的空间，以及压缩后数据库的大小；没有可删除的记录时不能执行清理。预计释放的空间按待删除记录占服务历史的比例折算，再加上已经空出的空间。这只是估算，实际释放的空间可能与估算值不同。数据量很大、精确计数超时时，记录数改用近似值，并标注“记录数为近似值”。

![选择保留天数后的数据库页面](/images/database/1.png)

::: tip 升级后的一次性变化
包含此功能的版本首次启动时，会删除 `service_histories` 表上一个冗余的 `created_at` 单列索引（同一列已由组合索引覆盖）。删除后空出的空间会显示在 **现在压缩可回收** 中，执行一次压缩即可还给磁盘。
:::

### 删除规则

保留天数可选 30 天（默认）、90 天、180 天，或自定义 1–3650 天。清理会删除：

- 超出保留天数的逐服务器服务历史（服务监控 1 天、7 天、30 天图表使用的数据）；
- 15 分钟汇总记录（30 天状态条使用的数据）中，超出保留天数的部分。**汇总记录始终至少保留 30 天**：保留天数少于 30 天时，汇总记录仍保留 30 天；
- 已删除服务遗留的全部历史，不论时间。

保留少于 30 天时，30 天图表将不完整；少于 7 天时，7 天图表也不完整。30 天状态条不受影响。

删除在后台分批进行，每批之间留出间隔，期间 Agent 上报和页面访问照常进行。页面会显示当前阶段（删除中、压缩中、重启中），完成后显示删除的记录数和释放的空间。

### 压缩（VACUUM）

只删除记录不会让数据库文件变小，空出的空间要在压缩（SQLite `VACUUM`）后才会还给磁盘。清理时可以选择压缩方式：

- **现场压缩**：删除完成后立即压缩。压缩期间整个数据库被锁定，面板的请求要等待数据库，最多约 5 秒后失败：后台可能卡顿或要求重新登录，Agent 在此期间上报的部分监控数据会丢失。压缩结束后自动恢复。
- **重启面板时压缩**：删除完成后面板自动重启，在启动时、开始提供服务之前压缩数据库。期间面板不可用，在线会话和 Agent 连接会断开，之后自动重连。此项需要面板由 Docker 或 systemd 托管，并配置了自动重启（如 Docker 的 `restart: always`、systemd 的 `Restart=always`）；面板只能识别运行环境，无法确认重启策略，没有配置自动重启时，面板退出后需要手动启动。识别不到这类环境时，此项不可选。
- **不压缩**：只删除记录，文件大小不变。空出的空间之后会被新数据复用；下次清理时选择压缩，可以一并回收。

页面会估算压缩耗时（按清理后剩余的数据量，约每 GiB 15 秒）并给出建议：现场压缩预计不超过 3 秒时，建议现场压缩；更久时建议重启面板时压缩；当前环境无法自动重启时，建议在空闲时段现场压缩，或者不压缩。默认选中建议的方式。

压缩需要额外的临时磁盘空间：SQLite 会先把压缩后的数据库写到临时目录，再写回原文件，并把被覆盖的内容记录在数据库旁的回滚日志中。页面会显示所需空间，约为当前数据库大小加上压缩后的大小。磁盘剩余空间不足时，页面只允许删除记录；即使在执行时才发现空间不足，面板也会跳过压缩，并在结果中说明。

重启面板时压缩如果失败，或者压缩过程中面板意外退出，面板仍会正常启动，不会再次尝试压缩，结果中会显示失败原因，删除的记录不受影响。

### 定期维护与“建议重启压缩”

面板每周日 04:00 自动维护一次数据库，调用 [`POST /api/v1/maintenance`](/guide/api.html#数据库维护接口) 的效果与此相同。维护不会无条件压缩整个数据库，而是按情况处理：

- **空出的空间不多**（少于数据库的 10%，且少于 64 MiB）：不做任何事，这些空间会被新数据复用。
- **数据库已是增量模式**：把空出的空间分成许多小批次还给磁盘，每批只短暂占用数据库，后台访问和 Agent 上报基本不受影响。
- **数据库还不是增量模式**：预计压缩不超过 3 秒时，直接压缩，同时转为增量模式；预计更久时跳过，只在日志中记录，以免长时间锁住数据库。

新安装的面板，数据库一开始就是增量模式。从旧版本升级的数据库，在第一次压缩（重启面板时压缩或现场压缩）之后转为增量模式，之后的定期维护都不再需要整库压缩。

数据库较大、空出的空间较多、又还不是增量模式时，此页面会提示 **建议重启压缩**。此时执行一次清理并选择 **重启面板时压缩**。清理会按所选保留天数删除较早的记录，并且无论保留天数多长，都会删除已删除服务遗留的历史（见[删除规则](#删除规则)）；保留天数越长，删除的记录越少。压缩完成后数据库转为增量模式，提示随之消失。面板无法自动重启时，可以在访问较少的时段选择 **现场压缩**。

::: tip 与旧版本的区别
旧版本的每周维护和 `POST /api/v1/maintenance` 每次都会压缩整个数据库，数据库较大时，压缩期间后台会卡顿、要求重新登录，Agent 上报的数据也会丢失。现在改为上面的按需处理：大数据库在转为增量模式之前，定期维护不会再压缩它。
:::

### 执行前先备份

删除的历史无法恢复。如果以后可能用到这些数据，请先在 **备份** 标签页做一次备份（确认框中也有 **前往备份** 的入口）。清理需要两次确认：第一次确认保留天数、预计删除量和压缩方式，第二次确认删除。

![第一次确认](/images/database/2.png)

![第二次确认](/images/database/3.png)

同一时间只能进行一项数据库清理、压缩或恢复：其中一项进行时，再发起其他操作会提示“另一项数据库清理或维护正在进行”。

### 启用 TSDB 时

启用 [TSDB](/guide/q15.html) 后，服务监控历史保存在 TSDB 中，`service_histories` 表不再使用。此时数据库标签页只显示占用，不显示清理功能，服务监控历史的保留期由 [`tsdb.retention_days`](/configuration/dashboard.html#tsdb) 控制。

## Web 应用防火墙

Web 应用防火墙依赖 **前端真实 IP 请求头** 识别来源 IP。配置真实 IP Header 前，请先阅读 [前端真实 IP 请求头](/guide/q12.html)，确认 Dashboard 读取到的是真实客户端 IP。

可以查看当前的封禁条目，并提供一些有用的信息：

- **IP** 被封禁者的 IP。
- **封禁标识** 被封禁者尝试攻击的资源标识，与 IP 一起作为封禁条目的标识。一般情况下为用户 ID，但也存在以下特殊情况：
  1. 尝试破解 gRPC 连接密钥；
  2. 尝试破解 API Token；
  3. 尝试登录不存在的用户；
  4. 手动封禁（通过“在线用户”页面）。
- **计数** 此封禁条目的封禁次数，数量越多则封禁时间越长。
- **封禁原因** 此封禁条目最后一次的封禁原因。
- **封禁时间** 此封禁条目最后一次的封禁时间。

如果当前用户为管理员，便可以手动删除封禁条目，也可以批量删除选中的封禁条目。
