# 初始化用户密码

当遗忘本地数据库中存储的用户密码时，无法直接找回明文密码，因为它已通过 `bcrypt` 加密。可以选择以下两种方法之一：

- **方法一（推荐）**：只重置指定用户的密码，其他用户和数据不受影响。
- **方法二**：清空用户表，让 Dashboard 重新创建默认账户。这会删除所有用户，副作用较大。

::: tip 升级后正确的密码也提示错误？
如果升级到 v2.6.0 及以上版本后，确定正确的密码也无法登录，很可能是反向代理转发的 Host 与浏览器地址不一致，而不是密码错误。请先参考 [登录常见问题](/guide/loginq.html#升级到-v2-6-0-及以上后提示密码错误) 自查，不需要重置密码。
:::

以下命令中的数据库路径以默认安装位置为例：

```plaintext
/opt/nezha/dashboard/data/sqlite.db
```

如果你的数据目录不同，请替换为实际路径。使用 Docker 部署时，请在宿主机上对挂载出来的数据目录执行这些命令。

---

## 方法一：只重置指定用户的密码（推荐）

### 1. 停止 Dashboard 并备份数据库

为了确保数据一致性和避免意外冲突，请先停止 Dashboard，再备份数据库：

```bash
cp /opt/nezha/dashboard/data/sqlite.db /opt/nezha/dashboard/data/sqlite.db.bak
```

---

### 2. 确认要重置的用户 ID

```bash
sqlite3 /opt/nezha/dashboard/data/sqlite.db "SELECT id, username FROM users;"
```

记下要重置的用户的 `id`（一个数字），下一步按这个 ID 选中该用户。

---

### 3. 生成新密码的哈希并更新该用户

使用 `htpasswd`（Debian/Ubuntu 的 `apache2-utils` 软件包，RHEL 系的 `httpd-tools` 软件包）生成新密码的 bcrypt 哈希。先把下面的 `USER_ID` 改为第 2 步查到的 ID，再在 Bash 中整段执行。`htpasswd` 会提示你输入两次新密码：

```bash
DB=/opt/nezha/dashboard/data/sqlite.db
USER_ID=1   # 替换为第 2 步查到的用户 ID

if HASH=$(htpasswd -nBC 10 "") && HASH=${HASH#:} \
  && [[ $HASH =~ ^\$2[aby]\$[0-9]{2}\$[./A-Za-z0-9]{53}$ && $USER_ID =~ ^[0-9]+$ ]]; then
  printf "UPDATE users SET password='%s', reject_password=0, token_version=token_version+1 WHERE id=%s;\nSELECT CASE changes() WHEN 1 THEN '已更新 1 行' ELSE '未找到该用户，未修改' END;\n" "$HASH" "$USER_ID" | sqlite3 "$DB"
else
  echo "哈希生成失败或用户 ID 无效，未修改数据库"
fi; unset HASH
```

- 输出「已更新 1 行」表示只修改了该用户；输出「未找到该用户，未修改」表示该 ID 不存在，请回到第 2 步核对。
- 两次输入的密码不一致，或按 `Ctrl+C`、`Ctrl+D` 取消时，命令会停止，不会修改数据库。
- 明文密码只在 `htpasswd` 的提示中输入；哈希经标准输入交给 `sqlite3`。两者都不会出现在命令行参数和 shell 历史中。
- `reject_password=0`：重新允许该用户使用密码登录（如果之前在个人信息中开启了“禁止密码登录”）。
- `token_version=token_version+1`：让该用户已有的登录会话失效。
- `unset HASH` 和 `fi` 写在同一行，是因为 `htpasswd` 读取密码时会丢弃已粘贴但尚未执行的内容，单独成行可能不会执行。

`htpasswd` 生成的是 `$2y$` 格式的哈希，Dashboard 可以识别。

可以再次查询，确认该用户仍在且 `reject_password` 为 `0`（将 `1` 替换为该用户 ID）：

```bash
sqlite3 /opt/nezha/dashboard/data/sqlite.db "SELECT id, username, reject_password FROM users WHERE id=1;"
```

---

### 4. 启动 Dashboard 并登录

启动 Dashboard，使用该用户名和新密码登录。确认无误后，可以删除第 1 步的备份文件。

---

## 方法二：清空用户表，恢复默认账户

::: warning 副作用
`DELETE FROM users;` 会删除**所有**用户，包括管理员和普通成员。重建的 `admin` 是一个新用户，副作用包括：

- 用户 ID 与原来不同。原用户名下的服务器、服务监控、告警规则、通知等数据仍按原用户 ID 记录，不再属于任何现有用户；普通成员需要重新创建，也看不到原来名下的数据。
- 原用户的 OAuth2 绑定失效，需要重新绑定。
- 每个用户有自己的 Agent 连接密钥，新用户会生成新的密钥。使用原用户密钥接入的 Agent 将无法连接（反复认证失败还会被 WAF 封禁），需要改用新密钥重新配置。

除非确实需要从头开始，否则请使用方法一。
:::

### 1. 停止 Dashboard 并备份数据库

```bash
cp /opt/nezha/dashboard/data/sqlite.db /opt/nezha/dashboard/data/sqlite.db.bak
```

---

### 2. 查询和清空用户表

使用 SQLite 命令行工具操作数据库：

1. **查看现有用户**：
   运行以下命令查看用户表内容：
   ```bash
   sqlite3 /opt/nezha/dashboard/data/sqlite.db "SELECT * FROM users;"
   ```
   这将列出当前所有用户的记录。

2. **清空用户表**：
   如果您确认需要重置用户表，可运行以下命令清空：
   ```bash
   sqlite3 /opt/nezha/dashboard/data/sqlite.db "DELETE FROM users;"
   ```

---

### 3. 重启 Dashboard 服务

完成数据库操作后，重新启动 Dashboard。

---

### 4. 登录默认账户

Dashboard 在初始化时会自动检测用户表是否为空。如果为空，将自动插入默认用户。  
您可以使用以下默认账户登录：
- **用户名**：`admin`
- **密码**：`admin`

---

## 后续操作

登录成功后，建议立即修改密码以提高安全性（使用方法二时必须修改默认密码）：
1. 点击 **头像 → 个人信息**。
2. 选择 **更新个人资料**。
3. 修改密码，建议设置一个复杂度较高的密码。

---

## 注意事项

- 修改数据库前，请确保已停止 Dashboard 并备份原始数据库文件。
- **谨慎操作**：清空用户表将移除所有用户数据，包括管理员用户。确认后再执行。
