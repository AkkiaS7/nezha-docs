# Initialize User Password

If you forget the user password stored in the local database, it cannot be retrieved as it is encrypted using `bcrypt`. Use one of the following methods:

- **Method 1 (recommended)**: Reset only the affected user's password. Other users and data are not affected.
- **Method 2**: Clear the user table so Dashboard creates the default account again. This deletes all users and has significant side effects.

::: tip Correct password rejected after an upgrade?
If the correct password stops working after upgrading to v2.6.0 or later, the cause is most likely that the reverse proxy forwards a Host that differs from the browser address, not a wrong password. See the [Login FAQ](/en_US/guide/loginq.html#incorrect-password-after-upgrading-to-v2-6-0-or-later) first; you do not need to reset the password.
:::

The commands below use the default database location:

```plaintext
/opt/nezha/dashboard/data/sqlite.db
```

Replace it with your actual path if your data directory is different. For Docker deployments, run these commands on the host against the mounted data directory.

---

## Method 1: Reset Only One User's Password (Recommended)

### 1. Stop the Dashboard and Back Up the Database

To ensure data consistency and prevent conflicts, stop the Dashboard first, then back up the database:

```bash
cp /opt/nezha/dashboard/data/sqlite.db /opt/nezha/dashboard/data/sqlite.db.bak
```

---

### 2. Find the Username to Reset

```bash
sqlite3 /opt/nezha/dashboard/data/sqlite.db "SELECT id, username FROM users;"
```

---

### 3. Generate a bcrypt Hash of the New Password

Use `htpasswd` (package `apache2-utils` on Debian/Ubuntu, `httpd-tools` on RHEL-based systems) to generate the hash. The following command prompts for the new password twice, so the password never appears on the command line or in the shell history:

```bash
HASH=$(htpasswd -nBC 10 "" | tr -d ':\n')
```

Dashboard accepts the `$2y$` hashes generated by `htpasswd`, as well as `$2a$` and `$2b$` bcrypt hashes from other tools. Do not put the plaintext password in a command argument, or it will remain in your shell history.

---

### 4. Update the User's Password

Replace `admin` in the command with the username found in step 2:

```bash
sqlite3 /opt/nezha/dashboard/data/sqlite.db "UPDATE users SET password='$HASH', reject_password=0, token_version=token_version+1 WHERE username='admin';"
unset HASH
```

- `reject_password=0`: allows the user to log in with a password again (if "Disable password login" was enabled on the profile page).
- `token_version=token_version+1`: invalidates the user's existing login sessions.
- Only the variable name `$HASH` appears in the command, so the hash itself is not written to the shell history.

You can query again to confirm the user still exists and `reject_password` is `0`:

```bash
sqlite3 /opt/nezha/dashboard/data/sqlite.db "SELECT id, username, reject_password FROM users WHERE username='admin';"
```

---

### 5. Start the Dashboard and Log In

Start the Dashboard and log in with the username and the new password. Once confirmed, you can delete the backup file from step 1.

---

## Method 2: Clear the User Table and Restore the Default Account

::: warning Side effects
`DELETE FROM users;` deletes **all** users, including administrators and members. The recreated `admin` is a new user, with these side effects:

- The user ID differs from before. Servers, services, alert rules, notifications, and other data are still recorded under the old user IDs and no longer belong to any existing user. Members must be recreated and cannot see the data they previously owned.
- OAuth2 bindings of the old users are lost and must be bound again.
- Each user has their own Agent connection secret, and the new user gets a new one. Agents connected with an old user's secret can no longer connect (repeated authentication failures are also blocked by the WAF) and must be reconfigured with the new secret.

Use Method 1 unless you really need to start over.
:::

### 1. Stop the Dashboard and Back Up the Database

```bash
cp /opt/nezha/dashboard/data/sqlite.db /opt/nezha/dashboard/data/sqlite.db.bak
```

---

### 2. Query and Reset the User Table

Use the SQLite command-line tool to interact with the database:

1. **Query Existing Users**:
   Run the following command to list all existing users:
   ```bash
   sqlite3 /opt/nezha/dashboard/data/sqlite.db "SELECT * FROM users;"
   ```

2. **Clear the User Table**:
   If you need to reset the user table, run the following command to delete all user records:
   ```bash
   sqlite3 /opt/nezha/dashboard/data/sqlite.db "DELETE FROM users;"
   ```

---

### 3. Restart the Dashboard

After modifying the database, restart the Dashboard to apply changes.

---

### 4. Login Using the Default Account

During initialization, the Dashboard checks if the user table is empty. If it is, a default user account is created automatically.  
You can log in with the following credentials:
- **Username**: `admin`
- **Password**: `admin`

---

## Post-Reset Actions

Once logged in, it is strongly recommended to change the password immediately for security reasons (with Method 2, you must change the default password):
1. Go to **Profile → Personal Info**.
2. Select **Update Profile**.
3. Set a new, secure password.

---

## Important Notes

- **Back Up Before Modifying**: Always stop the Dashboard and back up the database before making any changes.
- **Caution**: Clearing the user table will remove all existing user accounts, including administrators. Proceed only if you are certain about the operation.
